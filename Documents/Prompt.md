## 1. Project Identity
* **Name:** SolsticeSFG (Solstice Single-File Graphics)
* **Organization:** Equinox-Collective
* **Language:** Pure C (**C99** strictly). No C++, no GNU extensions, no compiler-specific tricks unless explicitly guarded behind `#ifdef` fallbacks.
* **License:** Dual-licensed (`Zlib OR MIT`). Never suggest or copy-paste GPL/AGPL/LGPL or copyleft snippets.
* **Primary Mission:** A lightweight, rock-solid, zero-dependency 2D graphics, font rendering, and UI foundation capable of running anywhere:
  1. Freestanding / bare-metal / custom display servers (e.g., `EquantOS` KMS/DRM or raw kernel framebuffer).
  2. Desktop environments and shells (e.g., `Windows` DIB/DXGI windows).
  3. Embedded systems and general indie applications.

## 2. Core Architectural Principles

### A. Modular Development -> Single-Header Amalgamation
* **Development happens modularly** inside `include/`, `src/`, `backends/`, `tests/`, and `tools/`.
* **Distribution happens as a single header** generated by our amalgamation tool into `dist/solsticesfg.h` (stb/miniaudio style: `#define SOL_IMPLEMENTATION` before `#include "solsticesfg.h"`).
* **Never** hand-edit files in `dist/`.
* **Amalgamation hygiene:**
  * All standard `#include` directives belong at the top of the public header (`include/`), guarded cleanly if freestanding overrides are needed.
  * Never place `#include` statements in the middle of `.c` files (except the internal header, which the amalgamator strips/resolves).
  * Every internal helper function across `src/*.c` must have a unique prefixed name (e.g., `sol__clip_rect`) or use `SOL_PRIVATE` (`static`), preventing redefinition errors when all `.c` files are concatenated into one file.

### B. Framebuffer-First & Backend Agnosticism
* The core library (`include/` + `src/`) **must never** import OS-specific headers (`<windows.h>`, `<X11/...>`, `<linux/fb.h>`, `<xf86drm.h>`).
* Core rendering operates strictly on an abstract pixel surface / raw memory buffer (`uint32_t *pixels`, `int width`, `int height`, `int stride`).
* OS windowing, display servers, input events, and buffer presentation live strictly inside `backends/`.

### C. Zero Mandatory Dependencies (Freestanding Friendly)
* Do not require external libraries (no SDL, Cairo, FreeType, stb_*, etc.) in the core.
* Standard C library calls (`malloc`, `free`, `memcpy`, `memset`, `math.h`) must be wrapped in overridable macros (e.g., `SOL_MALLOC`, `SOL_FREE`, `SOL_MEMCPY`) so an OS kernel or custom allocator can override them at compile time.
* Avoid dynamic allocations inside hot rendering loops (prefer stack allocation, caller-provided buffers, or arena/context pre-allocation).

### D. Context-Based API (No Hidden Global State)
* No global mutable variables. Every operation takes an explicit context/surface pointer (e.g., `sol_ctx_t *ctx` or `sol_surface_t *surf`).
* The library must be safe to use across multiple independent surfaces/threads simultaneously.

## 3. Code Quality, Safety & Style Invariants
* **Formatting:** Strictly follow `.clang-format` (4 spaces, K&R braces, right-aligned pointers `int *ptr`, 100-column limit).
* **Warnings:** Must compile with **zero warnings** under:
  `-std=c99 -Wall -Wextra -Werror -pedantic` (GCC/Clang) and `/W4 /WX` (MSVC).
* **Memory & Bounds Safety:**
  * Every drawing primitive must validate surface pointers, dimensions, and apply scissor/clipping bounds **before** writing to pixel memory.
  * Out-of-bounds buffer writes, integer overflows in stride/pixel calculations (`y * stride + x`), and division by zero are critical bugs.
* **Naming Convention:**
  * Public API functions: `sol_verb_noun(...)` (e.g., `sol_draw_rect`, `sol_surface_init`).
  * Public types: `sol_name_t` (e.g., `sol_color_t`, `sol_rect_t`).
  * Public macros/enums: `SOL_UPPER_SNAKE_CASE`.
  * Internal/private symbols: `sol__internal_name` or `static` inside translation units.

---

## 4. Testing Contract (`tests/`)
* Core logic and rendering must be **100% testable headlessly** (no monitor or window required).
* Every module, bug fix, or new primitive must have corresponding unit/pixel tests in `tests/`.
* Tests should verify:
  * Exact pixel output in memory buffers (`uint32_t` assertions).
  * Edge cases: 0x0 surfaces, negative coordinates, completely clipped primitives, integer overflow boundaries, alpha blending math.
* CI runs tests against **both** the modular build (`src/*.c`) and the amalgamated single-header build (`dist/solsticesfg.h`).

## 5. Rules for AI Assistants Working on This Repo
1. **Do not invent features or refactor unrelated modules** unless explicitly asked.
2. **Never write placeholder code** (`// ... rest of implementation`, `// TODO: implement`). Provide complete, compilable C99 code.
3. **Explain memory ownership and complexity** whenever introducing structs that hold pointers.
4. **Think about the amalgamator:** Before adding a new `.c` file, macro, or `typedef`, verify it won't collide with other files when concatenated into `dist/solsticesfg.h`.
5. **Respect the user's pace:** Small, verified, rock-solid increments over giant speculative rewrites.
